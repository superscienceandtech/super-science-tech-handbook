# Documentation Standards

## Every important document should include
- Purpose and scope
- Status (Draft, Proposed, Approved, Archived)
- Owner role or confirmed person
- Last updated / effective date where relevant
- Review date or review trigger
- Related documents and source repositories

## Accuracy rules
- Separate confirmed facts from proposals, assumptions, and unknowns.
- Use `TBD` when information is missing.
- Link to authoritative source repositories and approved decisions.
- Avoid copying rapidly changing implementation details into a static handbook.
- Never use this handbook to imply legal, security, or regulatory approval that has not happened.

## Confidentiality
Do not commit passwords, API keys, private keys, personal IDs, salary details, confidential client records, or restricted research data.
