# Contributing to the Handbook

## Workflow

1. Create a branch: `docs/<short-topic>` or `policy/<short-topic>`.
2. Make a focused change and link relevant evidence or source repositories.
3. Mark unverified details `TBD` and recommendations `Proposed`.
4. Open a Pull Request using the template.
5. Request review from the document owner or relevant domain owner.
6. Merge only after required review and checks pass.

## Quality checklist

- [ ] Is the content accurate and supported?
- [ ] Are assumptions clearly labelled?
- [ ] Is an owner named by role or confirmed identity?
- [ ] Are effective/review dates included for policies?
- [ ] Are secrets and personal/confidential data excluded?
- [ ] Are related pages linked?
- [ ] Are instructions tested if they describe executable steps?

## Writing style

Prefer clear, direct English, define acronyms on first use, and write for a new team member. Keep company-wide principles here; keep implementation details close to the code they describe.
